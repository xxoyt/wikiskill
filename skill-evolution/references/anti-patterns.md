# 技能进化（知行环）· 反模式与报错速查

> **这是全包唯一一处集中说"别这样做"的地方。** 其他文档讲怎么用，这里只讲**怎么用错**。
>
> 用法：装完先扫一遍 [一、二、三] 的标题，遇到怪事先查 [四、报错速查表]。
> 拿不准某个做法算不算反模式，搜本文件的关键词即可。

---

## 一、使用反模式（闭环流程本身）

### AP-01 在每个任务里跑完整闭环

- ❌ **别这样做**：干完一个任务就把 ①→⑦ 全走一遍，"反正自动化能跑"。
- **为什么错**：论文里 Inference Agent 执行任务时**刻意不读 Wiki**（避免混淆变量，实测读 Wiki 反而降低技能质量）。闭环是**离线批量**动作，在线只做轻量记录。
- ✅ **正确做法**：在线只做 ② 记录（≤10 行）；③④ 攒到 3–5 个任务后离线做。
- **症状**：Agent 越来越慢、回答开始"自我引用"过往结论、重复表述同一批经验。

### AP-02 让日常任务的 Agent 去读 `.wiki/`

- ❌ **别这样做**：在 `CLAUDE.md` / `AGENTS.md` 里写"每次任务前先读 `.wiki/` 全量知识"。
- **为什么错**：这是**角色隔离红线**。WikiSkill 论文的消融实验证实，执行任务的 Agent 读 Wiki 会引入混淆变量、降低技能质量。
- ✅ **正确做法**：日常任务只**写** `raw/`；`knowledge/` 与 `skills/` 由离线的复盘角色读。指令模板里已内置该约束，别去"优化"掉。
- **症状**：同一个坑被"记住"了但仍反复踩；记进来的经验与当前任务风马牛不相及。

### AP-03 用自评分当「可衡量」的证据

- ❌ **别这样做**：Agent 写完技能，自己评估"这个改进很有效"就标记采纳。
- **为什么错**：⑤ 门控第一问「可衡量」要求**≥2 个同域任务、用与提案前相同的判据独立复测**。自评分不算证据，这是防"一次性刷榜"的核心机制。
- ✅ **正确做法**：提案时就把基线判据写进 `impact_tracker.md`，之后拿同一把尺子复测。
- **症状**：技能库里全是"已验证有效"，但实际该踩的坑一个没少。

### AP-04 回滚技能时顺手把 `knowledge/` 也回滚了

- ❌ **别这样做**：验证失败的提案，连同记录它的模式一起删掉。
- **为什么错**：**双轨原则**——技能轨可回滚，知识轨**永不回滚**。"试过什么、为什么不行"是最有价值的资产，删了同一个坑必然再踩。
- ✅ **正确做法**：撤回 `skills/` 的改动，把失败原因**追加**进 `patterns.md`。
- **症状**：`patterns.md` 里同一类问题被"重新发现"好几次，编号不断增大。

### AP-05 一次提多个技能改进

- ❌ **别这样做**：一轮复盘顺手改 4 个技能，"效率高"。
- **为什么错**：违反**原子化**原则。效果不好时无法归因是哪个改动、哪一处逻辑导致的，只能整批回滚。
- ✅ **正确做法**：一轮只动一个技能（新增或修改），改动力求最小。
- **症状**：提案验证失败后，没人说得清该退回到哪一版。

### AP-06 技能文件不带「变更历史」

- ❌ **别这样做**：手写一个技能 md 丢进 `skills/`，只写正文。
- **为什么错**：第 4 问「可回滚」是**一票否决**。没有变更历史、无法恢复到上一版的技能，**无论多有效都不许采纳**。
- ✅ **正确做法**：用 `references/templates.md` 的技能模板，保留 `## 变更历史` 段，每次改动追加一行。
- **症状**：门控卡住一堆"其他方面都挺好"的提案。

### AP-07 把模式写成"注意细节"这类废话

- ❌ **别这样做**：`FM-007: 注意参数顺序，小心不要写错。`
- **为什么错**：模式的价值在于**可操作**。不含触发条件与解决方法的条目，下次遇到时 Agent 无法据以行动。
- ✅ **正确做法**：四要素齐全——触发条件 / 表现 / 根因 / 解决方案（照 `templates.md` 填）。
- **症状**：`patterns.md` 很长，但复盘时找不出任何可执行的规避动作。

### AP-08 在无关项目里自动创建 `.wiki/`

- ❌ **别这样做**：让定时任务"发现没有就建一个"。
- **为什么错**：会在随便一个目录里凭空长出目录，属于越界写入。所有脚本与自动化都设计为**发现 `.wiki/` 不存在就跳过并说明**。
- ✅ **正确做法**：在新项目**手动**跑一次初始化（说「初始化 wiki」或跑 `wiki_init.py`）。
- **症状**：车库里全是莫名其妙的 `.wiki/` 目录（比如在 `$HOME`、临时目录里）。

## 二、记录反模式（写 `raw/` 时）

### AP-09 记流水账

- ❌ **别这样做**：把每一步操作、每条命令、每次报错原文都贴进去。
- **为什么错**：轨迹是给**复盘**读的，不是日志。噪音会淹没关键决策点，让 ③ 提炼阶段无从下手。
- ✅ **正确做法**：一条轨迹 ≤10 行，**只记关键决策点、异常、有效技巧**。
- **症状**：`raw/` 单日文件几百行，复盘时一条模式也提炼不出来。

### AP-10 只记结论，不记根因

- ❌ **别这样做**：`结果：搞定。`
- **为什么错**：结论不含"当时为什么这么做"，换个场景就不能迁移——而「可迁移」正是第 3 问。
- ✅ **正确做法**：写清**可观察的现象 → 你的判断 → 采取了什么 → 为什么有效**。
- **症状**：`patterns.md` 里的模式换到另一个项目就不灵。

### AP-11 把敏感信息写进轨迹

- ❌ **别这样做**：报错日志里带着 API token、数据库密码、真实患者姓名／身份证号，原样贴进 `raw/`。
- **为什么错**：`.wiki/` 是**纯文本、且建议提交 Git**。写进去等于把凭据与个人隐私永久留在了仓库历史里。
- ✅ **正确做法**：凭据一律用 `<TOKEN>` 占位；业务数据脱敏或用字段名代替实际值。
- **症状**：`git log -p` 里能搜到密钥；合规审计过不去。

### AP-12 用工具替 Agent 编经验

- ❌ **别这样做**：让定时任务"就算没新轨迹也生成几条模式出来"。
- **为什么错**：凭空捏造的模式会污染知识库，且比没有更糟——Agent 会照着一本错误的书行事。
- ✅ **正确做法**：无新轨迹时明确输出**"无需维护"**。所有自动化 prompt 都写了这条，别删。
- **症状**：`patterns.md` 里出现从未真实发生的"高频失败模式"。

## 三、安装与运维反模式

### AP-13 把 hook 指向 AI 工具的私有目录

- ❌ **别这样做**：hook 命令写成指向 `~/.workbuddy/skills/...` 或任何工具私有路径。
- **为什么错**：换一台没装该工具的机器，hook 会**静默失效**——不报错、不提醒，你以为在运行其实没有。这正是旧版 `install_claude_hook.py` 被移除的原因。
- ✅ **正确做法**：项目级用**项目内相对路径**（`python ".wiki/scripts/wiki_remind.py"`），项目移动或 clone 后依然有效；由 `install.py` 生成，别手写。
- **症状**：hook 配好了但从来不提醒；换机器后失效。

### AP-14 在 Windows 上配 `.sh` 作为 hook 命令

- ❌ **别这样做**：hook 写 `bash ".wiki/scripts/wiki_remind.sh"`。
- **为什么错**：Claude Code 在 Windows 下执行 hook 走 cmd.exe / PowerShell，**没有 bash**，`.sh` 会静默失效。
- ✅ **正确做法**：Windows 用 `.py` 入口（`install.py` 会按平台自动选）。
- **症状**：同 AP-13——配了没反应。

### AP-15 把 Python 启动命令写死成 `python`

- ❌ **别这样做**：hook 与文档里一律写 `python`。
- **为什么错**：Linux / macOS 上常常**只有 `python3`**；Windows 上可能只有 `py -3`。写死会让 hook 静默失效。
- ✅ **正确做法**：`install.py` 写入 hook 时会自动探测（`detect_python()`）；手动跑命令时按自己机器替换。
- **症状**：装完提示正常，但提醒从不出现。

### AP-16 手改 `.claude/settings.json` 而不留备份

- ❌ **别这样做**：用编辑器手工往里加 hook，改完没检查 JSON 是否合法。
- **为什么错**：该文件可能还存着 API token 等配置。JSON 一旦多一个逗号，整个文件失效；本框架的脚本检测到非法 JSON 会**中止而不覆盖**（这是有意的）。
- ✅ **正确做法**：用 `install.py` 自动合并（它只动本框架的 hook 条目，其余原样保留）。确需手改就先复制一份备份。
- **症状**：`不是合法 JSON，已中止以免损坏配置` 这条提示反复出现。

### AP-17 用 `rm -rf .wiki` 之类的方式"重装"

- ❌ **别这样做**：嫌乱就把 `.wiki/` 整个删掉重来。
- **为什么错**：`.wiki/` 是你积累的**经验资产**，删掉等于清零重来。卸载流程**有意只摘 hook、不删数据**。
- ✅ **正确做法**：要重装就跑 `install.py --uninstall` 再重跑安装；`.wiki/` 会原样保留。
- **症状**：辛辛苦苦攒的经验一夜回到解放前。

## 四、报错速查表

> 先看「人话」一列判断是不是你知道的那个问题，再看右边怎么修。
> 本 skill **零第三方依赖、不联网**，所以几乎不会出现装包类错误。

| 你看到的报错（片段） | 人话 | 怎么修 |
|---|---|---|
| `UnicodeEncodeError: 'gbk' codec can't encode` | Windows 控制台默认编码装不下中文 | 脚本已内置修复；若仍有，运行前设 `PYTHONIOENCODING=utf-8` |
| `PermissionError: [Errno 13]` / `[WinError 5] 拒绝访问` | 文件被别的程序占用（编辑器、杀毒扫描）或无写权限 | 脚本会**自动重试**几次；仍失败就关掉占用它的编辑器/杀软，或换有权限的目录 |
| `FileNotFoundError` / `No such file or directory` | 路径不存在，多半是没站在项目根目录 | 用绝对路径，或先 `cd` 到项目根再执行 |
| `FileNotFoundError` 但**路径明明存在** | Windows 特有的误报：路径中间某一段其实是**文件**，不是目录 | 逐段检查路径，找出被同名文件占位的那一段，改名备份后重跑 |
| `.wiki` 存在但不是目录（`FileExistsError` / `[WinError 183] 当文件已存在时，无法创建该文件`） | `.wiki` 被一个**同名文件**占位，而它必须是个目录 | 确认该文件没用后**改名备份**（`.wiki` → `.wiki.bak`）再重跑；**别直接删** |
| 本想写文件却撞上同名目录（`IsADirectoryError`） | 该位置已有同名目录占着 | 换个项目目录，或先把同名目录移走 |
| `[Errno 28] No space left on device` | 磁盘满了 | 清理磁盘后重跑；已写入的文件会保留 |
| `bash: .wiki/scripts/wiki_init.sh: No such file or directory` | Windows 上没有 bash | 改用 `.py` 入口：`python .wiki/scripts/wiki_init.py` |
| `execvpe(/bin/bash) failed` | PATH 里的 `bash` 是 **WSL 中继**，机器上并没有真的 bash | 用 Git Bash 的完整路径，或直接改用 `.py` 入口 |
| `'python' 不是内部或外部命令` / `python: command not found` | 只有 `python3` 或 `py -3` | 换 `python3` 或 `py -3`；本 skill 只要求 Python 3.6+ |
| `json.decoder.JSONDecodeError` | `settings.json` 被改坏了（多半多个逗号） | 从备份恢复；或删掉该文件重跑 `install.py`（它会重新生成） |
| `ModuleNotFoundError: No module named '...'` | 本 skill **不需要任何第三方包** | 说明你跑错脚本了；只跑 `.wiki/scripts/` 或 `scripts/` 里自带的文件 |
| `不是合法 JSON，已中止以免损坏配置` | 脚本**主动拒绝**写入，保护你的配置 | 这不是崩溃，是保护。修好 JSON 后重跑 |
| 装完却**从不提醒** | hook 静默失效（见 AP-13/14/15） | 确认项目里有 `.wiki/`；重启会话；用 `install.py` 重新生 hook |
| `已存在，原样保留` / `跳过，以免覆盖` | 脚本**有意不覆盖**你已有的文件 | 这不是错误。要更新就先手动删除该文件再重跑 |
| 复盘跑完输出「无需维护」 | 近期没有新轨迹，属正常 | 不用管，不会凑内容 |
| 中文在 Windows 终端里显示成乱码 | 终端编码与 UTF-8 文件不匹配 | 文件保持 UTF-8；终端执行 `chcp 65001` |

## 五、自检

改完本 skill 后跑一次包体自检，能自动抓出编号冲突、围栏截断、目录树脱节等问题：

```bash
python scripts/selfcheck.py
python scripts/selfcheck.py --copy <副本目录>        # 顺带比对副本哈希
```
