# RSI 自改进工作流设计器（rsi-self-improvement-designer）

把 RSI（递归式自我改进）从概念变成你**具体项目里可运行的闭环**。
核心转变：从「人类手动调参提能力」改为「AI 闭环试错 → 验证 → 沉淀经验 → 改进自己」。

当你想给自己的代码库 / AI 工具加一个「自改进」机制、评估某工作流的 AI 自主权成熟度（L1–L5）、或把 RSI 方法论落到工程任务时，用它。

---

## 它在整条链里的位置

```
认知 (rsi-knowledge)  →  设计 (本 skill)  →  实现 (wikiskill)
  RSI 是什么？定级       给项目画自改进闭环      闭环里「沉淀经验」这步
  L 几？HCI 缺口？             ↓ 引用             直接套 .wiki/ 三层架构
                       复用 wikiskill 落地
```

- **上游**：设计前若需回顾完整概念、指标或产业数据，引用 `rsi-knowledge`。
- **下游**：闭环里「沉淀经验」这一步，直接复用 `wikiskill` 的 `.wiki/` 三层架构（Raw→Wiki→Skill，带验证-回滚），天然跨平台。

## 核心框架速查（设计时必须对齐）

### 五级自主权（人类退出 / AI 接管 的梯度）
| 级别 | 名称 | 人类负责 | AI 闭环接管 |
|---|---|---|---|
| L1 | 执行自主 | 设计任务、环境、更新策略 | 执行任务、更新 |
| L2 | 策略自主 | 设计任务、环境 | 设计更新策略（策略持久化） |
| L3 | 经验获取自主 | 设计环境 | 规划经验获取、执行、设计更新策略 |
| L4 | 环境适应自主 | 设定边界 | 与环境交互、设计更新策略 |
| L5 | 递归继承自主 | 设定边界 | 改进「改进系统本身」 |

### 环境-数据-模型四步闭环
1. **重构环境**：把原始工作区还原成可供 Agent 训练/评估的环境
2. **暴露缺口**：借新环境发现真实能力缺口，生成训练数据
3. **再训练/沉淀**：用生成数据训练任务模型；经验沉淀建议复用 `wikiskill` 的 `.wiki/` 三层架构
4. **迭代环境**：用更强模型推动下一轮环境迭代（形成闭环）

### 四大评估追问（避免「一次性刷榜」式伪改进）
- **可衡量**：独立评估下能否复现？
- **可保持**：改进能否持久不退化？
- **可迁移**：能否跨任务/领域复用？
- **可回滚**：失效时能否安全撤回？

### HCI 一句话
`HCI = (当前得分 − 基准得分) ÷ (100 − 基准得分) × 100`。真实任务执行（软件工程 52.6 / 工具调用 Agent 39.9）缺口最大 = RSI 红利最高。

## 设计工作流（五步）

1. **定位现状**：对照 L1–L5 判定当前级别，定下一步目标
2. **选落地切口**：按「反馈成本 / 可验证性 / 部署约束」三维选最优任务
3. **设计闭环**：套四步闭环，落到具体工程动作
4. **定义验收**：用四大追问为每个改进设独立验证与回滚
5. **输出方案**：按模板产出结构化文档

### 最优切口特征
优先选「反馈廉价、验证明确、部署链路短」的任务——代码编译修复、单测生成、回归测试、日志/报错诊断。
**软件工程与工具型 Agent 是各家发力第一站**，正是因为它们天然容易闭合 RSI 循环。
避免选反馈稀缺或验证冒险的领域（科研、机器人、医疗）。

## 通用性与跨平台约束（必须遵守）

- 本 skill 输出的方案保持**平台中立**：不假设只在 WorkBuddy 运行，也不硬编码任何工具私有目录（如 `~/.workbuddy/`）。
- 经验沉淀统一走 `wikiskill` 的 `.wiki/`（项目自包含、可提交 Git、跨机器迁移），使同一套自改进闭环在 **Claude Code / Codex / WorkBuddy** 等任意 agent 下都能运行。
- 引用其他 skill 的资源时，使用其项目内相对路径，而非工具私有绝对目录。

## 典型示例（独立开发者场景）

- **AI Coding 助手自改进**：把编译/测试报错标准化为环境 → AI 反复修 → 修通过的 pattern 沉淀进项目级 skill → 下一轮用更强模型提升测试覆盖
- **SaaS 项目运维自改进**：把 Redis 迁移/接口报错日志结构化为反馈 → Agent 诊断并沉淀修复经验
- **数据质量保障**：交付后真实反馈驱动更新 → 关键缺陷率下降、人工处理时间缩短（参考 Humanlaya 9.0%→3.7%）

---

## 注意事项

- 不要承诺 L5 级递归收益（缺乏充分验证），现实目标通常是 L2–L3
- 强调「独立评估」，反对自评分刷榜
- 经验沉淀优先复用 `wikiskill`（跨平台、带验证-回滚），不另造轮子、不锁定单一 agent
